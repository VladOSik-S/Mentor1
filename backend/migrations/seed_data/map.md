Map в Go — это встроенная структура данных, реализующая ассоциативный массив (хеш-таблицу). Map хранит пары ключ-значение и обеспечивает быстрый доступ к значениям по ключу со сложностью примерно O(1). Можно сказать - среднеконстантная сложность. Это когда `а * O(1)` где `a` не зависит от количества элементов `N`.

## Основные понятия и термины

### Хеш-функция (Hash Function)

Хеш-функция преобразует ключ произвольной длины в целое число фиксированной длины. Важные свойства хеш-функции:

- **Стабильность**: одинаковые ключи всегда дают одинаковый хеш
- **Хорошее распределение**: похожие ключи дают сильно различающиеся хеши
- **Устойчивость к коллизиям**: минимизация вероятности одинаковых хешей для разных ключей

Какая самая простая хеш функция? Ну например взять 1 букву у слова. Или суммировать цифры числа пока не получим одну цифру. 789 -> 24 -> 6.

### Коллизия (Collision)

Ситуация, когда разные ключи получают одинаковый хеш или должны быть размещены в одном слоте. Есть два варианта, что можно сделать:

1) Методы открытой адресации - идем дальше по какому-то порядку, пока не найдем свободную. еще можно хеш от хеша взять.
2) Цепочки переполнения - элементы с одинаковым результатом хеш-функции помещаются в связный список. каждая ячейка хеш-таблицы содержит указатель на начало списка элементов, которые хешируются в эту позицию.

### Bucket (Бакет)

Логическая единица хранения в хеш-таблице, содержащая несколько пар ключ-значение. В Go каждый бакет хранит до 8 элементов.

### Load Factor (Коэффициент заполнения)

Отношение количества элементов к общему числу слотов. Когда load factor превышает определённый порог, происходит расширение (growth) таблицы. В Go традиционно это около 6.5/8 (≈80%).

### Probe Sequence (Последовательность проб)

Алгоритм поиска альтернативных позиций при возникновении коллизии в open-addressed хеш-таблицах. Они разные бывают. Линейный, квадратичный.

## Старая реализация map (до Go 1.24)

### Архитектура

Старая реализация использовала классическую хеш-таблицу с бакетами и цепочками переполнения (overflow buckets).

#### Структура hmap

```go
type hmap struct {
    count     int        // количество элементов в map
    flags     uint8      // флаги состояния
    B         uint8      // log2 от количества бакетов
    noverflow uint16     // количество overflow buckets
    hash0     uint32     // seed для хеш-функции
    buckets   unsafe.Pointer  // указатель на массив бакетов
    oldbuckets unsafe.Pointer // указатель на старые бакеты при росте
}
```

#### Структура bucket (bmap)

```go
type bmap struct {
    tophash [8]uint8  // старшие 8 бит хеша для каждого ключа
    // далее идут 8 ключей
    // затем 8 значений
    // указатель на overflow bucket
}
```

### Особенности старой реализации

> Тут не надо учить, но если запомните - круто.

**Организация памяти**: ключи и значения хранятся раздельными блоками (все 8 ключей, затем все 8 значений), что уменьшает padding и экономит память.

**Tophash оптимизация**: первый байт хеша ключа хранится в массиве tophash. При поиске сначала сравниваются tophash значения, и только при совпадении происходит сравнение полного ключа.

**Overflow buckets**: когда бакет переполняется, создаётся связанный список дополнительных бакетов.

**Инкрементальный рост**: при достижении load factor около 80%, map начинает постепенный рост. Новый массив бакетов создаётся с удвоенным размером, но данные копируются не сразу, а постепенно при каждой операции записи.

### Эвакуация

Эвакуация — это процесс, при котором элементы из старых бакетов поэтапно переносятся в новые бакеты при изменении размера таблицы (например, при **увеличении пространства** или **реорганизации для уменьшения количества коллизий**). Эта процедура позволяет сохранить эффективность операций поиска, вставки и удаления даже при росте числа элементов или коэффициента заполнения, предотвращая чрезмерное замедление работы таблицы. Обычно эвакуация сопровождается вычислением новых индексов для существующих элементов с помощью хеш-функции и распределением их по новому массиву.

То есть если коэффициент заполненности больше 6.5 то у мапы происходит эвакуация. **Поэтапная**, чтобы не было жестких просадок производительности в моменте. При каждой операции **записи или обновления** данные переносятся в новую мапу.

### Компиляторная магия

Map операции компилируются в вызовы runtime функций:

- `v := m[key]` →
  `runtime.mapaccess1(maptype, hmap, key)`
- `v, ok := m[key]` →
  `runtime.mapaccess2(maptype, hmap, key)`
- `m[key] = value` →
  `runtime.mapassign(maptype, hmap, key, value)`
- `delete(m, key)` →
  `runtime.mapdelete(maptype, hmap, key)`

### Структура maptype

Для каждого типа map (например, `map[string]int`, `map[int]string`) компилятор создаёт структуру maptype, содержащую метаинформацию:

```go
type maptype struct {
    typ       _type
    key       *_type    // тип ключа
    elem      *_type    // тип значения
    bucket    *_type    // тип бакета
    keysize   uint8     // размер ключа
    valuesize uint8     // размер значения
    bucketsize uint16   // размер бакета
}
```

## Новая реализация: Swiss Table (Go 1.24+)

### Что такое Swiss Table

Swiss Table — это дизайн хеш-таблицы, разработанный Google в 2017 году для C++. В Go 1.24 встроенный тип map был полностью переписан на основе этой архитектуры.

### Ключевые отличия Swiss Table

**Группы (Groups)**: массив разбивается на логические группы по 8 слотов. Каждая группа имеет 64-битное контрольное слово.

**Контрольное слово (Control Word)**: 64-битное значение (8 байт), где каждый байт соответствует одному слоту в группе. Байт содержит:

- 1 бит: указывает, пустой ли слот, удалённый или используется
- 7 бит: младшие биты хеша ключа (h2)

**Разделение хеша**: хеш делится на две части:

- h1 (старшие 57 бит): используется для выбора группы
- h2 (младшие 7 бит): хранится в контрольном слове

**SIMD оптимизация**: контрольное слово позволяет сравнивать 8 значений h2 параллельно за одну операцию, используя SIMD инструкции или эмуляцию через битовые операции.

### Архитектура Swiss Table в Go

```
Group 0                          Group 1
┌──────────────────────────────┐ ┌──────────────────────────────┐
│ Slot 0│1│2│3│4│5│6│7│        │ │ Slot 0│1│2│3│4│5│6│7│        │
│ [key-value pairs]            │ │ [key-value pairs]            │
└──────────────────────────────┘ └──────────────────────────────┘
│ Control Word (64 bits)       │ │ Control Word (64 bits)       │
│ [h2][h2][h2]...[h2]          │ │ [h2][h2][h2]...[h2]          │
└──────────────────────────────┘ └──────────────────────────────┘
```

### Операции в Swiss Table

**Вставка**:

1. Вычислить hash(key) и разделить на h1 и h2
2. Использовать h1 для выбора группы: `h1 % num_groups`
3. Проверить контрольное слово на наличие ключа (сравнение h2)
4. Если ключа нет, найти пустой слот
5. Если группа полная, перейти к следующей группе

**Поиск**:

1. Вычислить hash(key) и получить h1, h2
2. Найти группу по h1
3. Сравнить h2 с контрольным словом группы (параллельно за одну операцию)
4. Для каждого совпадения h2 проверить полный ключ
5. Если не найдено, продолжить поиск в следующей группе

### Преимущества Swiss Table

- **Скорость**: до 60% быстрее в микробенчмарках по сравнению со старой реализацией
- **Улучшенная работа с кешем**: компактное расположение метаданных в памяти
- **Меньше cache misses**: благодаря контрольному слову и SIMD
- **Лучшая производительность при высоком load factor**: можно поддерживать более высокий коэффициент заполнения
- **Экономия памяти**: более эффективное использование памяти для больших map

### Extendible Hashing в Go

Для поддержки инкрементального роста (требование Go для низкой latency) каждый map разбивается на несколько независимых Swiss Tables:

- Каждая таблица хранит максимум 1024 элемента
- Переменное количество старших бит хеша используется для выбора таблицы
- При росте одной таблицы остальные не затрагиваются
- Это ограничивает максимальную задержку одной операции вставки

## Важные особенности map в Go

### Передача по ссылке

Map в Go — это ссылочный тип. Переменная map содержит указатель на структуру hmap. **При передаче map в функцию копируется только указатель, не данные.**

```go
func modifyMap(m map[string]int) {
    m["new"] = 100  // изменяет оригинальную map
}
```

### Небезопасность для конкурентного доступа

Map **не является потокобезопасным**. Одновременное чтение и запись из разных горутин вызовет панику. Но если только операции чтения то ей норм.

**Безопасно**:

- Множественное чтение без записи из разных горутин

**Небезопасно**:

- Одновременная запись
- Одновременное чтение и запись

**Решения для concurrent доступа**:

```go
// 1. Использование mutex
type SafeMap struct {
    mu sync.RWMutex
    data map[string]int
}

func (sm *SafeMap) Get(key string) (int, bool) {
    sm.mu.RLock()
    defer sm.mu.RUnlock()
    val, ok := sm.data[key]
    return val, ok
}

// 2. sync.Map (для специфичных use-cases)
var m sync.Map
m.Store("key", "value")
val, ok := m.Load("key")
```

### Отсутствие гарантий порядка

Map в Go **не гарантирует порядок итерации**. Более того, порядок намеренно рандомизируется между запусками программы.

### Изменение во время итерации

Go явно разрешает изменение map во время итерации с определёнными семантиками:

- Удалённый элемент не будет показан, если до него ещё не дошли
- Обновлённое значение будет показано, если до него ещё не дошли
- Новый элемент может быть показан или нет

### Zero value

Zero value для map — это `nil`. В nil map нельзя добавлять элементы, но можно читать (всегда вернёт zero value типа значения).

```go
var m map[string]int  // m == nil
val := m["key"]       // val == 0, ok
m["key"] = 1          // panic: assignment to entry in nil map
```

## Частые вопросы на собеседованиях

### Теоретические вопросы

**1. Что такое map в Go и как она работает внутри?**

Map — это хеш-таблица, которая хранит пары ключ-значение. Внутри использует хеш-функцию для преобразования ключа в индекс бакета. В Go 1.24+ используется Swiss Table архитектура с группами по 8 слотов и контрольными словами для быстрого поиска.

**2. Какая сложность операций с map?**

- Поиск: O(1) в среднем случае, O(n) в худшем
- Вставка: O(1) в среднем случае
- Удаление: O(1) в среднем случае

**3. Является ли map потокобезопасной?**

Нет. Map не является потокобезопасной. Одновременное чтение и запись из разных горутин приведёт к runtime panic. Для безопасного использования нужен mutex или sync.Map.

**4. Что произойдёт, если читать из nil map?**

Чтение из nil map безопасно и вернёт zero value для типа значения и false для второго возвращаемого значения. Запись в nil map вызовет panic.

**5. Почему нельзя взять адрес элемента map?**

Элементы map могут перемещаться в памяти при росте таблицы. Если бы существовали указатели на элементы, они стали бы невалидными после реорганизации.

**6. Какие типы можно использовать как ключи map?**

Ключами могут быть любые сравнимые типы: числа, строки, указатели, каналы, интерфейсы, структуры и массивы, содержащие только сравнимые типы. Нельзя использовать: slice, map, function.

**7. В чём разница между старой реализацией map и Swiss Table?**

Swiss Table использует контрольные слова для параллельной проверки 8 слотов одновременно, что уменьшает количество проверок и cache misses. Это даёт до 60% прирост производительности в некоторых сценариях.

**8. Что такое load factor и зачем он нужен?**

Load factor — это отношение количества элементов к количеству слотов. Когда он превышает ~80%, map расширяется. Это необходимо для поддержания O(1) сложности операций.

**9. Как происходит рост map?**

Рост происходит инкрементально: создаётся новый массив бакетов удвоенного размера, но данные копируются постепенно при каждой операции записи, а не все сразу. Это снижает latency.

**10. Можно ли удалять элементы map во время итерации?**

Да, Go явно разрешает модификацию map во время итерации. Удалённые элементы не будут показаны, если итератор до них ещё не дошёл.

### Практические задачи

**Задача 1: Подсчёт частоты слов**

```go
func wordFrequency(text string) map[string]int {
    words := strings.Fields(text)
    freq := make(map[string]int)

    for _, word := range words {
        freq[word]++
    }

    return freq
}
```

**Задача 2: Two Sum с использованием map**

```go
func twoSum(nums []int, target int) []int {
    seen := make(map[int]int) // value -> index

    for i, num := range nums {
        complement := target - num
        if idx, ok := seen[complement]; ok {
            return []int{idx, i}
        }
        seen[num] = i
    }

    return nil
}
```

**Задача 3: Группировка элементов по ключу**

```go
type Person struct {
    Name string
    Age  int
}

func groupByAge(people []Person) map[int][]Person {
    groups := make(map[int][]Person)

    for _, person := range people {
        groups[person.Age] = append(groups[person.Age], person)
    }

    return groups
}
```

**Задача 4: Проверка наличия дубликатов**

```go
func containsDuplicate(nums []int) bool {
    seen := make(map[int]struct{}) // используем struct{} для экономии памяти

    for _, num := range nums {
        if _, exists := seen[num]; exists {
            return true
        }
        seen[num] = struct{}{}
    }

    return false
}
```

**Задача 5: LRU Cache (усложнённая)**

```go
type LRUCache struct {
    capacity int
    cache    map[int]*Node
    head     *Node
    tail     *Node
}

type Node struct {
    key   int
    value int
    prev  *Node
    next  *Node
}

func Constructor(capacity int) LRUCache {
    return LRUCache{
        capacity: capacity,
        cache:    make(map[int]*Node),
        head:     &Node{},
        tail:     &Node{},
    }
}

func (c *LRUCache) Get(key int) int {
    if node, ok := c.cache[key]; ok {
        c.moveToHead(node)
        return node.value
    }
    return -1
}

func (c *LRUCache) Put(key int, value int) {
    if node, ok := c.cache[key]; ok {
        node.value = value
        c.moveToHead(node)
        return
    }

    node := &Node{key: key, value: value}
    c.cache[key] = node
    c.addToHead(node)

    if len(c.cache) > c.capacity {
        removed := c.removeTail()
        delete(c.cache, removed.key)
    }
}

// moveToHead, addToHead, removeTail методы опущены для краткости
```

**Задача 6: Безопасная concurrent map**

```go
type SafeCounter struct {
    mu sync.RWMutex
    counters map[string]int
}

func NewSafeCounter() *SafeCounter {
    return &SafeCounter{
        counters: make(map[string]int),
    }
}

func (sc *SafeCounter) Inc(key string) {
    sc.mu.Lock()
    defer sc.mu.Unlock()
    sc.counters[key]++
}

func (sc *SafeCounter) Value(key string) int {
    sc.mu.RLock()
    defer sc.mu.RUnlock()
    return sc.counters[key]
}
```

## Практические советы

### Инициализация

```go
// Плохо: nil map
var m map[string]int
m["key"] = 1  // panic!

// Хорошо: инициализация с make
m := make(map[string]int)
m["key"] = 1

// Хорошо: map literal
m := map[string]int{
    "one": 1,
    "two": 2,
}

// Оптимизация: с заданной ёмкостью
m := make(map[string]int, 100)  // предотвращает реаллокации
```

### Проверка существования ключа

```go
// Всегда используйте форму с двумя возвращаемыми значениями
val, ok := m["key"]
if ok {
    // ключ существует
}

// Или кратко
if val, ok := m["key"]; ok {
    // используем val
}
```

### Удаление элементов

```go
delete(m, "key")  // безопасно, даже если ключа нет
```

### Итерация

```go
// Только ключи
for key := range m {
    fmt.Println(key)
}

// Ключи и значения
for key, val := range m {
    fmt.Println(key, val)
}

// Только значения (редко используется)
for _, val := range m {
    fmt.Println(val)
}
```

### Оптимизация памяти для значений-флагов

```go
// Используйте struct{} вместо bool для экономии памяти
set := make(map[string]struct{})
set["item"] = struct{}{}

if _, exists := set["item"]; exists {
    // item есть в множестве
}
```

## Заключение

Map в Go — мощная и хорошо оптимизированная структура данных. Понимание её внутреннего устройства, особенно с новой Swiss Table реализацией в Go 1.24, важно для написания эффективного кода и успешного прохождения технических собеседований. Ключевые моменты для запоминания:

- Map реализована как хеш-таблица с O(1) операциями в среднем случае
- Go 1.24 использует Swiss Table с контрольными словами и SIMD оптимизациями
- Map не является потокобезопасной — требуется sync.Mutex или sync.Map
- Порядок итерации не гарантирован и специально рандомизирован
- Map — референсный тип, передаётся по ссылке
- Инкрементальный рост обеспечивает предсказуемую latency
