Garbage Collector (сборщик мусора) в Go — это автоматический механизм управления памятью, который освобождает неиспользуемую память без участия разработчика. В Go используется конкурентный, не-генерационный сборщик мусора, основанный на алгоритме трёхцветной маркировки и очистки (tricolor mark-and-sweep).

## Как работает GC

### Трёхцветный алгоритм

GC классифицирует все объекты в памяти на три категории:

**Белые объекты** — потенциальный мусор, объекты, которые ещё не были обработаны алгоритмом. В начале цикла сборки мусора все объекты помечаются белым цветом.

**Серые объекты** — объекты, которые достижимы из корней (глобальные переменные, стек), но их дочерние ссылки ещё не просканированы. Это фронт работы для GC.

**Чёрные объекты** — полностью просканированные объекты, все ссылки из которых уже обработаны. Они гарантированно живые и не будут удалены.

### Фазы работы GC

Процесс сборки мусора состоит из двух основных фаз:

**Фаза маркировки (Mark Phase)** — GC начинает с корневых объектов (стек, глобальные переменные) и помечает их серым цветом. Затем последовательно выбирает серые объекты, помечает их чёрными и переводит все их дочерние ссылки в серый цвет. Процесс продолжается до тех пор, пока не останется серых объектов.

**Фаза очистки (Sweep Phase)** — после завершения маркировки все оставшиеся белые объекты считаются мусором и память освобождается. В Go память помечается доступной для перезаписи и постепенно возвращается системе.

### Конкурентная работа

Главная особенность GC в Go — его конкурентность. Основная работа по маркировке происходит параллельно с выполнением горутин приложения, что минимизирует паузы Stop-The-World (STW). Короткие STW-паузы необходимы только для синхронизации фаз.

## Write Barrier (Барьер записи)

Write Barrier — это критически важный механизм, который включается во время фазы маркировки. Когда горутина изменяет указатель и создаёт новую связь между объектами, барьер записи отслеживает это изменение. Если чёрный объект начинает ссылаться на белый, барьер автоматически перекрашивает белый объект в серый. Это гарантирует, что живые объекты не будут ошибочно удалены во время конкурентной работы GC.

## Escape Analysis

Escape Analysis — это анализ на этапе компиляции, который определяет, будет ли объект размещён на стеке или в куче. Объекты на стеке освобождаются автоматически при выходе из функции, не требуя работы GC. Объекты "убегают" в кучу в следующих случаях:

- Возвращаются из функции по указателю
- Сохраняются в замыкании
- Передаются в интерфейс
- Размер структуры слишком велик для стека

Проверить результаты Escape Analysis можно командой:

```
go build -gcflags="-m"
```

## Настройка и оптимизация

### Параметр GOGC

GOGC управляет частотой запуска сборщика мусора. По умолчанию значение равно 100, что означает: GC запускается, когда размер кучи увеличивается на 100% относительно живых объектов после предыдущей сборки.

Увеличение GOGC (например, до 200) делает сборку реже, снижая нагрузку на CPU, но увеличивая потребление памяти. Уменьшение GOGC (например, до 50) приводит к более частым сборкам, экономя память за счёт роста нагрузки на процессор.

Установить значение можно через переменную окружения:

```
GOGC=200 ./myapp
```

Или в коде:

```
debug.SetGCPercent(200)
```

### Параметр GOMEMLIMIT

GOMEMLIMIT позволяет задать жёсткий лимит памяти для приложения. Это полезно в контейнеризированных средах, где нужно гарантировать, что приложение не превысит выделенный объём памяти.

```
GOMEMLIMIT=2GiB ./myapp
```

### Практические рекомендации

- Минимизируйте количество аллокаций в куче, используя значения вместо указателей где возможно
- Используйте `sync.Pool` для переиспользования временных объектов
- Избегайте создания большого количества маленьких объектов в горячих путях кода
- Мониторьте метрики GC через `runtime.ReadMemStats()` и pprof

## Частые вопросы на собеседованиях

### Теоретические вопросы

**Как работает GC в Go?**
Опишите трёхцветный алгоритм, фазы mark и sweep, конкурентность выполнения.

**Что такое Write Barrier?**
Объясните механизм отслеживания изменений указателей во время конкурентной маркировки.

**Что такое Stop-The-World паузы?**
Короткие периоды остановки всех горутин для синхронизации фаз GC.

**Чем отличается стек от кучи?**
Стек: быстрая память для локальных переменных, автоматическое освобождение. Куча: управляется GC, для долгоживущих объектов.

**Что такое Escape Analysis?**
Анализ компилятора, определяющий место размещения объекта (стек или куча).

### Практические вопросы

**Как настроить частоту работы GC?**
Через GOGC и GOMEMLIMIT.

**Как уменьшить нагрузку на GC?**
Минимизировать аллокации, использовать sync.Pool, предпочитать значения указателям.

**Как измерить влияние GC на производительность?**
Использовать pprof, runtime.ReadMemStats(), мониторить GC паузы.

**Когда объект размещается в куче, а не на стеке?**
При возврате указателя, хранении в замыкании, передаче в интерфейс.
