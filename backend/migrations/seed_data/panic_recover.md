## Что такое Panic

Panic в Go — это встроенная функция, которая останавливает обычное выполнение программы и переводит **горутину** в режим **паники** (panicking mode). Когда происходит паника, программа начинает **разматывать стек** (stack unwinding), выполняя при этом все отложенные функции (deferred functions).

Паника может быть вызвана двумя способами:

- Явным вызовом функции `panic()` с любым значением в качестве аргумента
- Ошибкой времени выполнения (runtime error), например, обращением к несуществующему индексу массива или разыменованием nil-указателя

## Что такое Defer

Ключевое слово `defer` откладывает выполнение функции до момента завершения окружающей функции. Отложенные функции сохраняются в специальном списке и выполняются в порядке **LIFO** (Last In, First Out) — последняя отложенная функция выполнится первой.

Три важных правила работы defer:

- Аргументы отложенной функции вычисляются в момент объявления defer
- Отложенные функции выполняются в обратном порядке объявления
- Отложенные функции могут читать и изменять именованные возвращаемые значения функции

## Что такое Recover

Recover — это встроенная функция, которая позволяет **перехватить панику** и вернуть контроль над горутиной[web:6]. Функция recover работает только при вызове внутри отложенной функции (deferred function). В нормальном режиме работы программы recover возвращает nil.

Когда горутина находится в состоянии паники, вызов recover возвращает значение, переданное в panic, и останавливает дальнейшее разматывание стека.

## Как работает механизм Panic/Recover

### Базовый пример с Panic

```
package main

import "fmt"

func main() {
    fmt.Println("Начало программы")
    panic("что-то пошло не так")
    fmt.Println("Эта строка не выполнится")
}
```

Программа завершится с ошибкой, и последняя строка не выполнится.

### Перехват паники с Recover

```
package main

import "fmt"

func main() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("Паника перехвачена:", r)
        }
    }()

    fmt.Println("Начало программы")
    panic("что-то пошло не так")
    fmt.Println("Эта строка выполнится")
}
```

Программа не завершится аварийно — паника будет перехвачена и программа продолжит работу.

### Конвертация паники в ошибку

```
func doSomething() (err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("произошла паника: %v", r)
        }
    }()

    panic("критическая ошибка")
    return nil
}
```

Использование **именованных возвращаемых значений** (named return values) позволяет конвертировать панику в обычную ошибку.

## Важные особенности и ограничения

### Recover работает только в deferred функции

```
// НЕ РАБОТАЕТ
func main() {
    defer recover() // Паника не будет перехвачена
    panic("ошибка")
}

// РАБОТАЕТ
func main() {
    defer func() {
        recover() // Паника будет перехвачена
    }()
    panic("ошибка")
}
```

Recover должен вызываться непосредственно в отложенной функции, а не через промежуточный вызов[web:7].

### Recover не работает между горутинами

```
func main() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("Паника перехвачена")
        }
    }()

    go panic("паника в другой горутине")
    time.Sleep(1 * time.Second)
}
```

Каждая горутина имеет собственный стек и собственную цепочку defer. Паника в одной горутине не может быть перехвачена defer из другой горутины.

### Порядок выполнения defer при панике

```
func example() {
    defer fmt.Println("Defer 1")
    defer fmt.Println("Defer 2")
    defer fmt.Println("Defer 3")
    panic("ошибка")
}
```

Вывод будет в обратном порядке: Defer 3, Defer 2, Defer 1.

## Best Practices

### Когда использовать Panic

- Только для **исключительных ситуаций** (exceptional conditions), когда программа не может продолжить выполнение
- Для критических ошибок инициализации или конфигурации
- Когда обнаружено нарушение инвариантов программы
- В большинстве случаев лучше использовать явный возврат ошибок через error

### Когда использовать Recover

- На верхних уровнях приложения (например, в HTTP-обработчиках) для предотвращения полного краха сервера
- При работе с ненадёжным кодом или внешними библиотеками
- Для конвертации паник во внутренние ошибки в библиотеках
- Всегда ограничивайте область действия recover минимально возможным участком кода

### Антипаттерны

```
// ПЛОХО: использование паники для обычного flow control
func divide(a, b int) int {
    if b == 0 {
        panic("деление на ноль") // Лучше вернуть error
    }
    return a / b
}

// ХОРОШО: использование error для ожидаемых ситуаций
func divide(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("деление на ноль")
    }
    return a / b, nil
}
```

### Паттерн для библиотек

Внутри библиотеки можно использовать panic для упрощения кода, но публичный API должен возвращать error.

```
func ParseJSON(data []byte) (result interface{}, err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("ошибка парсинга: %v", r)
        }
    }()

    return parseInternal(data), nil
}

func parseInternal(data []byte) interface{} {
    // Внутренний код может использовать panic
    if len(data) == 0 {
        panic("пустые данные")
    }
    // ...
}
```

## Частые вопросы на собеседованиях

### Теоретические вопросы

**1. В чём разница между panic и error в Go?**

Error — это стандартный механизм обработки ожидаемых ошибок через возвращаемые значения. Panic — это механизм для исключительных ситуаций, когда программа не может продолжить выполнение. Error нужно явно проверять, panic останавливает выполнение программы.

**2. Может ли recover перехватить панику из другой горутины?**

Нет, каждая горутина имеет собственный стек вызовов и собственную цепочку defer. Паника в горутине может быть перехвачена только defer внутри той же горутины.

**3. Что произойдёт, если вызвать recover вне deferred функции?**

Recover вернёт nil и не окажет никакого эффекта. Recover проверяет, что вызов происходит из правильного контекста — из отложенной функции, активной в момент паники.

**4. В каком порядке выполняются deferred функции?**

В порядке LIFO (Last In, First Out) — последняя объявленная defer выполнится перво. Это соответствует разматыванию стека.

**5. Может ли deferred функция изменить возвращаемое значение?**

Да, если используются именованные возвращаемые значения (named return values). Deferred функция выполняется после вычисления return, но до фактического возврата из функции.

**6. Что происходит с deferred функциями при панике?**

Все deferred функции выполняются в обычном режиме во время разматывания стека. Это гарантирует освобождение ресурсов даже при панике.

**7. Когда следует использовать panic?**

Только для действительно исключительных ситуаций и невосстановимых ошибок. В большинстве случаев предпочтительнее явный возврат error.

**8. Можно ли вызвать panic с nil?**

Да, panic принимает любое значение интерфейса interface{}, включая nil. Однако это плохая практика, так как усложняет диагностику.

**9. Что такое stack unwinding?**

Процесс последовательного выхода из функций по стеку вызовов с выполнением всех deferred функций. Происходит при панике до тех пор, пока паника не будет перехвачена recover или программа не завершится.

**10. Как правильно логировать информацию о панике?**

В deferred функции с recover нужно сохранить значение паники и stack trace для последующего анализ. Можно использовать debug.Stack() для получения стека вызовов.

### Практические задачи

**Задача 1: Базовое использование recover**

Напишите функцию, которая безопасно вызывает произвольную функцию и возвращает error, если произошла паника.

```
func SafeCall(fn func()) (err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("паника: %v", r)
        }
    }()

    fn()
    return nil
}
```

**Задача 2: Защита от паники в HTTP-обработчике**

Создайте middleware для защиты HTTP-сервера от паник.

```
func RecoveryMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    defer func() {
        if r := recover(); r != nil {
            log.Printf("Паника: %v\n%s", r, debug.Stack())
            http.Error(w, "Internal Server Error",
            http.StatusInternalServerError)
        }
    }()

    next.ServeHTTP(w, r)
    })
}
```

**Задача 3: Работа с defer и именованными возвращаемыми значениями**

Что выведет эта функция?

```
func example() (result int) {
    defer func() {
        result++
    }()
    return 5
}

func main() {
    fmt.Println(example()) // Выведет: 6
}
```

Deferred функция может изменять именованное возвращаемое значение result после выполнения return.

**Задача 4: Множественные defer**

Предскажите вывод программы:

```
func main() {
    defer fmt.Println("A")
    defer fmt.Println("B")
    defer fmt.Println("C")
    fmt.Println("Start")
}

// Вывод:
// Start
// C
// B
// A
```

**Задача 5: Recover в цикле**

Напишите функцию, которая обрабатывает слайс функций и продолжает работу даже если одна из них вызывает панику.

```
func ProcessAll(funcs []func()) []error {
    var errors []error

    for i, fn := range funcs {
        err := func() (err error) {
            defer func() {
                if r := recover(); r != nil {
                    err = fmt.Errorf("функция %d: паника %v", i, r)
                }
            }()
            fn()
            return nil
        }()
        
        if err != nil {
            errors = append(errors, err)
        }
    }
    
    return errors
}
```

**Задача 6: Вопрос с подвохом**

Почему этот код не перехватывает панику?

```
func broken() {
    defer recover() // НЕ РАБОТАЕТ!
    panic("ошибка")
}
```

Recover должен вызываться внутри deferred функции, а не просто как deferred вызов. Правильный вариант:

```
func correct() {
    defer func() {
        recover() // Работает
    }()
    panic("ошибка")
}
```

**Задача 7: Цепочка паник**

Что произойдёт, если вызвать panic внутри deferred функции, которая обрабатывает другую панику?

```
func main() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("Первая паника:", r)
            panic("вторая паника") // Новая паника заменит первую
        }
    }()
    panic("первая паника")
}
```

Новая паника заменяет старую, и если её не перехватить — программа завершится с последней паникой.

**Задача 8: Аргументы defer вычисляются сразу**

Что выведет программа?

```
func main() {
    i := 0
    defer fmt.Println(i) // Вычислится сейчас
    i++
    fmt.Println(i)
}

// Вывод:
// 1
// 0
```

Аргументы defer вычисляются в момент объявления defer, а не в момент выполнения.

## Дополнительные термины для собеседования

- **Call stack** (стек вызовов) — структура данных, хранящая информацию о вызовах функций
- **Stack trace** — последовательность вызовов функций, приведших к текущей точке выполнения
- **Goroutine** — лёгкий поток выполнения, управляемый Go runtime
- **Runtime error** — ошибка времени выполнения, автоматически вызывающая панику
- **Named return values** — именованные возвращаемые значения функции
- **LIFO** (Last In, First Out) — принцип работы стека: последний добавленный элемент извлекается первым
- **Unwinding** (разматывание) — процесс выхода из вложенных функций
- **Invariant** (инвариант) — условие, которое должно всегда выполняться в программе
